{/* ───────── 2 为什么 ───────── */}
<Slide kicker="01 · Motivation" title="为什么需要后训练？">
  <div class="cols">
    <div>
      预训练只优化一件事：**预测互联网文本的下一个 token**。得到的 base model 知识丰富，但：

      <ul>
        <li>不会稳定地**遵循指令**：常常续写问题，而不是回答</li>
        <li>没有**偏好**：有用 / 无害 / 诚实都不是训练目标</li>
        <li>推理、工具调用、格式这类**能力需要被“激发”**</li>
      </ul>
    </div>
    <Figure title="同一个 prompt，两种模型" n={1} caption="Base model 把输入当作文档续写；后训练后的模型把它当作请求来完成。">

      </div>

  </div>
  <Step n={2}><div class="note">后训练的算力通常只占总量的一小部分，但决定了模型的**行为、风格和推理方式**。</div></Step>

{/* ───────── 4 SFT ───────── */}
<Slide kicker="03 · SFT" title="监督微调：先学会“像助手一样说话”" steps={2}>
  <div class="cols wide-r">
    <div>
      <TeX block tex={String.raw`\mathcal{L}_{\text{SFT}}=-\,\mathbb{E}_{(x,y)\sim\mathcal{D}}\sum_{t}\log\pi_\theta(y_t\mid x,y_{<t})`} />
      <ul>
        <li>数据：人写或强模型生成的示范；**质量 ≫ 数量**</li>
        <li>套上 **chat template**，只在回答上算 loss</li>
        <li>局限：只模仿“好”的样本，没见过“差”的；上限受示范质量限制</li>
      </ul>
    </div>
    <Figure title="Loss masking" n={3} caption="Prompt 与 response 拼成一条序列，prompt token 的 loss 被 mask 掉。">
      <SFTMask client:load />
    </Figure>
  </div>
</Slide>

{/* ───────── 5 RM ───────── */}
<Slide kicker="04 · Preference" title="偏好数据与奖励模型" steps={2}>
  <div class="cols wide-r">
    <div>
      评价“哪个更好”比写出“最好的答案”容易得多。用成对比较 <TeX tex={String.raw`(x, y_w, y_l)`} /> 训练一个打分器：
      <TeX block tex={String.raw`\mathcal{L}_{\text{RM}}=-\log\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big)`} />
      <ul class="small">
        <li>通常由 SFT 模型 + 标量输出头初始化</li>
        <li>偏好来源：人类标注、AI 反馈（RLAIF / Constitutional AI）</li>
        <li>RM 只是人类偏好的**近似**，会有偏差（如偏爱长回答）</li>
      </ul>
    </div>
    <Figure title="Bradley–Terry reward model" n={4} caption="RM 把每个回答映射成标量，P(A≻B) 由分数差经过 sigmoid 给出。">
      <PrefRM client:load />
    </Figure>
  </div>
</Slide>

{/* ───────── 7 KL β ───────── */}
<Slide kicker="06 · KL regularization" title="β 控制“追奖励”与“不跑偏”的平衡">
  <div class="kl-head">
    <TeX tex={String.raw`\max_\pi\ \mathbb{E}_{y\sim\pi}[r(y)]-\beta\,\mathrm{KL}(\pi\,\|\,\pi_{\text{ref}})\ \ \Longrightarrow\ \ \pi^*(y)=\frac{1}{Z}\,\pi_{\text{ref}}(y)\,e^{r(y)/\beta}`} />
  </div>
  <Figure title="Interactive · closed-form optimal policy" n={6} caption="β→∞ 时 π* 退回 π_ref；β→0 时 π* 塌缩到奖励最高的回答。这个闭式解正是 DPO 的出发点。">
    <KLBeta client:load />
  </Figure>
</Slide>

{/* ───────── 8 DPO vs RL ───────── */}
<Slide kicker="07 · DPO" title="DPO：把 RL 变成一个分类损失">
  <TeX block tex={String.raw`\mathcal{L}_{\text{DPO}}=-\log\sigma\Big(\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)}-\beta\log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\Big)`} />
  <p class="small muted">由 π* ∝ π_ref·e^(r/β) 反解出 r = β log(π*/π_ref) + β log Z，代入 Bradley–Terry 后 Z 相消 —— “你的语言模型其实就是一个奖励模型”。</p>
  <table class="cmp">
    <thead><tr><th></th><th>PPO-RLHF</th><th>DPO</th></tr></thead>
    <tbody>
      <tr><td>数据</td><td>在线采样（on-policy）</td><td>离线偏好对（off-policy）</td></tr>
      <tr><td>显式奖励模型</td><td>需要</td><td>不需要（隐式）</td></tr>
      <tr><td>显存中的模型</td><td>Actor / Critic / RM / Ref</td><td>Policy / Ref</td></tr>
      <tr><td>工程复杂度</td><td>高：采样、调参、稳定性</td><td>低：像 SFT 一样训练</td></tr>
      <tr><td>探索与上限</td><td>能发现数据之外的更好回答</td><td>受限于已有偏好数据分布</td></tr>
    </tbody>
  </table>
</Slide>

{/* ───────── 9 GRPO/RLVR ───────── */}
<Slide kicker="08 · GRPO / RLVR" title="可验证奖励 + 组内相对优势">
  <div class="cols" style="gap:40px">
    <ul class="small">
      <li>**RLVR**：数学答案对比、代码跑单元测试 → 规则给出 0/1 奖励，不需要 RM，难以被“讨好”</li>
      <li>**GRPO**（DeepSeekMath）：每个 prompt 采样 G 个回答，用组内统计量当 baseline，**去掉 Critic**</li>
    </ul>
    <div>
      <TeX block tex={String.raw`\hat A_i=\frac{r_i-\operatorname{mean}(r_{1..G})}{\operatorname{std}(r_{1..G})}`} />
      <p class="small muted">同一回答的所有 token 共享 Â_i；DeepSeek-R1 用它训练长链推理。</p>
    </div>
  </div>
  <Figure title="Interactive · group-relative advantage" n={7} caption="答对的少数样本获得大的正优势。Dr. GRPO 指出 ÷std 会让过易/过难题权重偏大，并带来长度偏差。">
    <GRPOGroup client:load />

{/* ───────── 10 Risks ───────── */}
<Slide kicker="09 · Pitfalls" title="风险：模型会优化你写下的，而不是你想要的" steps={1}>
  <div class="cols wide-r">
    <ul class="small">
      <li>**Reward hacking**：利用 RM 或验证器漏洞，如改测试、凑格式</li>
      <li>**过度优化**（Goodhart）：代理分数上涨，真实质量下降</li>
      <li>**Sycophancy / 长度偏差**：迎合用户、越写越长</li>
      <li>**熵塌缩**：探索消失，pass@k 不升反降</li>
      <li>**对齐税**：在部分基础能力上的退化</li>
    </ul>
    <Figure title="Reward model overoptimization" n={8} caption="示意图，曲线形态参考 Gao et al. 2023。缓解手段：KL 约束、RM 集成与定期刷新、早停、验证器加固、人工抽检。">
      <Overopt client:load />
    </Figure>
  </div>

{/* ───────── 11 Summary ───────── */}
<Slide kicker="10 · Takeaways" title="总结">
  <div class="sum">
    <Step n={1}><div><b>SFT</b> 教会格式与基本行为：示范的质量决定起点。</div></Step>
    <Step n={2}><div><b>偏好 / RM</b> 把“哪个更好”变成可优化的信号，但它只是代理。</div></Step>
    <Step n={3}><div><b>RL + KL</b> 在追奖励与保持能力之间取平衡；DPO 是它的离线闭式捷径。</div></Step>
    <Step n={4}><div><b>RLVR / GRPO</b> 用可验证奖励规模化推理训练，是当前前沿的主线。</div></Step>
    <Step n={5}><div><b>奖励设计</b> 永远是核心难题：你优化什么，就得到什么。</div></Step>
